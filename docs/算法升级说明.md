# ChainCoxswain（链舵）算法升级说明（P0 修复 + P1/P2 新算法）

本轮按任务书直接修改项目代码：先修复订单语义、双端一致性与历史泄漏（P0），
再实现动态安全库存、需求预测、Monte Carlo 概率仿真、临界点搜索升级与反向干预
优化（P1），最后接入多维风险、分仓识别与 Agent/MCP/前端/报告（P2）。

## 二、新算法公式、输入、输出与适用条件

### 1. 动态安全库存与再订货点（inventory_policy.py）
- 公式：`SS = z * sqrt(L̄·σD² + μD²·σL²)`，`ROP = μD·L̄ + SS`
- 输入：逐日需求序列（≥14 天）、交期样本（≥2 个，否则 σL=0 并标注）、目标服务水平 0.90/0.95/0.99（z=1.2816/1.6449/2.3263）
- 输出：recommendedSafety、recommendedROP、inventoryPosition（在手+确认在途−预留）、needsReorder/belowROP、notes/fallbackReason
- 适用条件：需求与交期近似独立、提前期需求近似正态；ADI≥1.32 时标注正态近似偏弱并建议 Croston/SBA 复核；历史不足回退录入安全库存并给出原因

### 2. 需求预测（demand_forecast.py）
- 分类：Syntetos-Boylan-Croston（ADI 1.32 / CV² 0.49 切分）→ smooth/erratic/intermittent/lumpy
- 方法：smooth→MA7 或 SES；erratic→SES；intermittent/lumpy→Croston-SBA；显著趋势→Holt 线性（半均值变化 >15% 判定）
- 输入：逐日需求序列；输出：逐日预测序列 + mu/sigma/cv/adi/趋势/方法/回退原因
- 约束：缺失日按 0 需求计入统计但**不等同于观测零需求**（标注 obsDays/nonZeroDays）；<14 天回退固定日均；截尾上修由 censored.py 的缺货小时速率法提供（零售数据），关系型数据无缺货日不套用

### 3. Monte Carlo 缺货概率（risk_probability.py）
- 流程：历史残差 bootstrap 逐日需求 + 到货偏移 empirical 分布 → 每次抽样跑一次确定性 simulate → 聚合
- 输出：7/14/30 天缺货概率、预计未满足量、P95 缺口、首次缺货日 p10/p50/p90、跌破安全库存概率
- 可复现：固定 seed（默认 42）、n 可配（默认 1000）
- 诚实边界：需求历史 <14 天 → `available=false` + `scenarioOnly` 情景分析 + reason，**不输出概率**

### 4. 临界点搜索升级（engine.find_threshold / find_joint_threshold）
- 保留倍增+整数二分（单维单调情景）；新增 `orderScope`（orderIds/supplier 组）；新增 joint（需求增长×供应延期）
- joint 用线性扫描而非二分，返回 `monotone` 实测标记；基准已缺货返回 `already` + `recovery`（seekRecovery 时）

### 5. 反向干预优化（intervention.py）
- 最小补货量（二分，补货量单调）、最晚可行到货（线性扫描）、最小需求削减（二分）、最小加急天数（线性扫描 ≤4 天默认上限）、组合方案（加急×到货日×补货量）
- 约束：maxReplenQty（仓容/供应能力）、leadDays（供应商交期）、maxExpediteDays；约束内不可行 → `feasible=false` + 原因，不推荐
- 成本：仅当 unitCost 存在时输出 `cost = 补货量 × 单价 ×(1+加急溢价%)`，否则 cost=null + 说明

### 6. 多维风险与分仓（risk_dimensions.py）
- 六维：shortage / volatility / fulfillment（准时率、平均延期、满足率）/ excess（覆盖天数+占用资金）/ warehouse（覆盖离散度）/ criticality（年消耗金额代理）
- 优先级：规则分层 P0–P3（返回命中规则列表），**不使用加权综合分**，避免缺概率/损失数据时伪造精度
- 分仓：SKU+warehouse 单元；他仓库存仅在 transship={enabled,leadDays,costPerUnit} 提供时计为可用，否则单独列出并标注
