# ChainCoxswain（链舵）比赛演示脚本（3–5 分钟）

> 演示前准备：`start.bat` 启动后端（无 Key 也可，Agent 走规则演示模式且明确标记）；
> 浏览器打开 `index.html`；确认右上角数据源为"演示数据"。
> 若已配置 `DASHSCOPE_API_KEY`，把脚本中"规则演示模式"替换为"真实千问 API"说法即可，其余流程一致。

---

## 0–30 秒：一句话定位 + 架构

**台词要点**：
"ChainCoxswain 是一个把**大模型决策**和**确定性仿真**分开的供应链风险系统。
千问负责决定'测谁、测什么、下一步怎么调'，但所有缺货数字都由确定性引擎计算——
模型不允许、也不可能编造库存数字。今天我们看三件事：怎么自主发现风险临界点、
怎么让评委看懂 Agent 的每一步推理、以及千问办公怎么真正产出 Excel/Word/PPT。"

**操作**：切到「数据总览」→「数据导入」，展示演示数据 6 个物料与 5 笔采购单。

---

## 30–90 秒：经典样例 + 临界点搜索（模块 E 回归基准）

**台词要点**：
"这是评委最关心的经典样例：M-001 库存 80、每天用 10，第 7 天到货 100。
延期 2 天没事；延期 3 天，第 9 天开始缺货 10 件——所以临界点是 3 天。
引擎用**倍增试探 + 整数二分**找到这个最小整数，每一轮都记录在案。"

**操作**：切到「手动情景模拟」→ 选 M-001 → 到货延期 2 天运行（不缺货）→ 改 3 天运行
（首次缺货 2026-11-03，缺口 10）→ 点「搜索临界点」显示 threshold=3 与逐轮日志。

---

## 90–180 秒：千问 Agent 决策面板（模块 B，重点）

**台词要点**：
"现在让千问 Agent 自主完成整个流程。请注意三点：
**第一**，它先调风险清单、再查物料、再搜临界点——顺序来自 SOP 而不是随机；
**第二**，每一轮都会显示'上一轮发现了什么、所以这一轮改了什么参数'——比如先搜到
M-002 需求上涨 22% 就缺货，下一轮就用 22 去比较干预方案；
**第三**，右边每个结论都标注来自哪个工具，最后一张结论卡明确写着
'结论数字全部来自工具返回结果'。"

**操作**：切到「千问 Agent 决策」→ 点击「运行 Agent」→ 等待 10–30 秒 →
逐条展开时间线：Round 1 风险清单 → Round 2/3 临界点搜索 →
Round N 干预方案比较 → 底部约束行（轮数/调用数/预算全部 ✓）→
结论三卡（最脆弱物料 / 临界点 / 干预方案）。
*如无 Key：页面顶部显示"规则演示模式（未配置 API Key）"——如实说明这是降级路径，配置 Key 后同一循环由千问驱动。*

---

## 180–270 秒：四组对照实验（模块 E）

**台词要点**：
"为什么需要 Agent？看对照实验。G1 静态预警只能告诉你有风险，给不出临界点；
G2 固定参数每样测一次'延期 3 天'，会漏掉真正的临界值；
G3 规则自适应能 100% 找到临界点、误差为 0，但测试顺序和取舍是写死的；
G4 千问 Agent 在**与 G3 相同的公平预算**下达到同样的 100% 检出、0 误差，
并且过程可解释、结论可追溯。地面真值表在页面下方，用穷举搜索验证，不玩文字游戏。"

**操作**：切到「对照实验」→ 点「运行对照」→ 展示四组柱状图（读出页面实测数值，
G3/G4 检测率应为 100%、临界点误差 0）→ 展开地面真值表对照。

---

## 270–330 秒：真实数据 + 数据边界（模块 A）

**台词要点**：
"接上比赛的真实数据 A.zip：632 个单元、19 个产品、81 个地理，快照日
**2021-03-01**——我们如实标注'历史数据'，绝不冒充实时。注意两个诚实点：
数据里没有采购订单，所以延期类测试会显示'不适用'或'基线已缺货'；
回测只重放 2021-03-02 之后的留出数据，**训练数据不会泄漏进测试**。"

**操作**：切到「数据导入」→「加载 A.zip」→ 展示来源 pill 变为
"A.zip 历史数据（快照 2021-03-01）"、4 个数据质量块、回测卡片
（632 单元，累计缺口以页面实测为准，演示数据下约 3500 万件）。

---

## 330–390 秒：千问办公协作（模块 C，收尾）

**台词要点**：
"最后是千问办公。注意：**千问办公不等于千问 API**——这是一个独立的 MCP Server，
7 个工具全部真实可调。我们本地已经完成了 stdio 和 HTTP 桥接的全部自动化测试；
在千问办公客户端里，用户说'分析当前库存风险，找出最脆弱的物料，自动运行压力测试，
推荐应对方案，并生成供应链风险分析报告'，它就会调这些工具取真实数据，
并生成**可编辑的** Excel、Word、PPT——不是一段总结文字。"

**操作**：切到「千问办公协作」→ 展示 MCP 连接状态与 7 个工具 → 逐个点测 2–3 个工具
（返回真实 JSON）→ 「复制任务指令」→ 「导出任务包」→
「生成报告」下拉选择 xlsx → 下载并打开展示 4 张工作表（风险清单/临界点/干预方案/数据来源与假设）。

**结束语**："所有数字来自确定性引擎；所有业务动作留给人；系统没有下单按钮——这是设计底线。"

---

## 备用：若现场无网络 / 无 Key

- 全程可用：离线打开 `index.html` + 后端无 Key 运行；
- Agent 面板显示"规则演示模式"标签 —— 主动说明这是明确标记的降级路径，
  配置 `DASHSCOPE_API_KEY` 后同一循环由真实千问驱动（现场可演示 `/api/qwen/status`）。
